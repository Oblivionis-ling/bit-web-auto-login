# BIT-Web Auto Login v1.3 Phase 3 Update Baseline

本文档记录 `BITWebAutoLogin.Management.psm1` 中 v1.2.5 PowerShell 更新器的既有行为。Phase 3 将其作为行为参考与 fallback；本阶段不修改或删除旧更新器。

## 远端信息获取

- 仓库固定为 `Oblivionis-ling/bit-web-auto-login`。
- API 基址固定为 `https://api.github.com/repos/Oblivionis-ling/bit-web-auto-login`。
- 请求设置 `Accept: application/vnd.github+json` 与 `User-Agent: BIT-Web-Auto-Login-Manager`。
- 优先读取 `/releases/latest`。
- Release 必须同时满足非 draft、非 prerelease、`tag_name` 非空。

## Release fallback

当最新 Release 不可用时，旧更新器会查询 `/commits/main`，校验 40 位十六进制提交 SHA，并下载该 SHA 对应的 GitHub source archive。

Phase 3 的 Native Manager 将收口为 Release-only。`main` fallback 仅保留在旧 PowerShell fallback 中，不进入新的正式更新 UI。

## 版本与 SHA 判断

- Release 通道以 Release tag 作为标识。
- main 通道以完整 commit SHA 作为标识。
- 已安装标识保存在 `%LOCALAPPDATA%\BITWebAutoLogin\update-state.json`。
- 当仓库与远端标识均相同时，旧更新器判断为已经是最新版本。
- Release 包内 `settings.json` 的 `Version` 必须与 `v{Version}` 标签一致。

旧更新器没有执行完整的语义化版本大小比较；Native Manager 必须补充严格的 `vMAJOR.MINOR.PATCH` 解析与禁止降级规则。

## 下载 URL 白名单

旧更新器要求归档 URL：

- scheme 必须为 `https`；
- host 必须为 `api.github.com`；
- path 必须以 `/repos/Oblivionis-ling/bit-web-auto-login/zipball/` 开头。

旧实现校验初始 URL，但依赖 `Invoke-WebRequest` 的默认重定向行为，没有再次验证最终重定向主机。Native Manager 必须手动处理重定向并逐跳校验。

## ZIP 下载与临时目录

- 每次使用 `%TEMP%\BITWebAutoLogin-update-{guid}` 唯一目录。
- ZIP 保存为 `source.zip`。
- 解压到独立 `source` 子目录。
- `finally` 中删除临时目录。

## 归档与项目结构校验

旧更新器要求解压后只有一个根目录，并至少包含：

```text
AutoLogin.ps1
BITWebAutoLogin.psm1
RunHidden.vbs
settings.json
Install.ps1
Uninstall.ps1
```

旧实现使用 `Expand-Archive`，没有显式逐 entry canonical path 校验。Native Manager 必须增加 Zip Slip、绝对路径、符号链接及异常体积防护。

## PowerShell 语法校验

旧更新器在部署前递归检查所有 `.ps1` 和 `.psm1`：

```powershell
[System.Management.Automation.Language.Parser]::ParseFile(...)
```

任何文件存在语法错误都会拒绝更新。Native Manager 必须保留这层校验。

## 部署方式

旧更新器调用新包中的：

```powershell
Install.ps1 -InstallDirectory $InstallDirectory
```

计划任务创建、兼容旧任务、凭据处理和启动监控仍由既有安装器负责。Native Manager 不应在 C# 中重写这些业务逻辑。

## 更新状态保存

安装完成后，旧更新器通过临时文件写入并移动生成 `update-state.json`，字段包括：

```text
Repository
Channel
Identifier
DisplayVersion
UpdatedAtUtc
```

## 失败恢复

旧更新器保证临时下载目录会被清理，但没有针对正式目录文件替换建立完整 backup/rollback 流程。若 `Install.ps1` 已覆盖部分文件后失败，需要依赖人工修复。

Native Manager Updater 必须在替换前备份所有将被覆盖的程序文件，失败时恢复旧文件并重新运行旧安装器。

## credential 与 settings 语义

- `Install.ps1` 在没有 `-RefreshCredential` 时保留已有 `credential.xml`。
- 更新包不应包含或覆盖 `credential.xml`。
- 当前安装器会复制包内 `settings.json`；它既包含版本，也包含网络检测等用户可配置值。

Native Manager 更新时将以新包 settings 为默认值，保留旧 settings 中除 `Version` 外的已有配置值，并使用新包版本作为最终 `Version`。凭据文件不读取、不复制、不移动。

## v1.3 Release 资产基线

正式更新不再使用 GitHub 自动生成的 source archive。预期 Release 资产：

```text
BITWebAutoLogin-v1.3.0-win-x64.zip
BITWebAutoLogin-v1.3.0-win-x64.zip.sha256
```

Release asset 必须包含编译后的 Native Manager 与 Updater helper；否则不具备自动安装资格。
