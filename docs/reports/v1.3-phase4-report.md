## 3. 最终选择

最终采用方案 C：

```text
SelfContained = true
PublishSingleFile = true
EnableCompressionInSingleFile = true
PublishTrimmed = false
PublishReadyToRun = false
DebugType = None
DebugSymbols = false
```

选择原因：

- 无需安装 .NET；
- Manager 和 Updater 均可独立启动；
- 文件数量少，Installer、Updater 和 rollback 更容易审计；
- 解包体积比多文件方案减少约 146.6 MiB；
- ZIP 体积也是三种方案中最小；
- 真实 WPF、嵌入字体和健康检查未发现 single-file compression 兼容问题。

没有启用 trimming，也没有启用 ReadyToRun。

## 8. 版本一致性机制

Canonical source：

```text
manager/Directory.Build.props → 1.3.0
```

Build 开始前必须满足：

- canonical version 是严格三段式；
- `settings.json Version` 等于 canonical version；
- Manager FileVersion 等于 canonical version；
- Updater FileVersion 等于 canonical version；
- 包根目录、ZIP 和 SHA 文件名包含相同版本；
- manifest version 为相同版本。

任一不一致都会终止构建，不会自动改写版本。

连续两次 clean build 的内部 manifest 内容及所有文件 SHA-256 完全一致：

```text
ManifestContentEqual = true
Manifest SHA-256 = 407E89B2609C363B3DDD44893ABF0CC9FC97867A0F925E7ABDAC583419C7A73D
```

ZIP 自身会因 ZIP entry 时间戳产生不同 hash；任务书未要求 bit-for-bit ZIP。每次构建都会生成与本次 ZIP 精确对应的 `.sha256`，最终校验结果为 `ChecksumMatch=True`。

受保护的 `AutoLogin.ps1` 内部算法版本字符串仍为 `1.2.5`，没有修改。产品/安装版本由 canonical version 与 `settings.json` 表示为 `1.3.0`。这是遵守“登录核心零改动”要求后的明确版本语义区分。

## 9. Release manifest

`release-manifest.json` 包含：

```json
{
  "schemaVersion": 1,
  "version": "1.3.0",
  "rid": "win-x64",
  "selfContained": true,
  "singleFile": true,
  "compressed": true,
  "trimmed": false,
  "readyToRun": false,
  "manager": "BITWebManager.exe",
  "updater": "BITWebUpdater.exe",
  "files": []
}
```

`files` 保存 manifest 之外每个文件的稳定相对路径、字节数与 SHA-256。它用于构建一致性和诊断，不替代外部 ZIP SHA-256 或未来代码签名。

## 25. 已知风险

1. 真实 `%LOCALAPPDATA%\BITWebAutoLogin` 和真实计划任务没有执行升级；本阶段使用隔离 Installer TestMode，避免破坏当前正常环境。真实用户目录演练推迟到 Phase 6 RC。
2. fresh install 的凭据输入 UI 没有自动化点击；测试使用隔离 DPAPI `PSCredential`，生产仍调用已有 `Get-Credential`。
3. 生产 Scheduled Task XML rollback 已实现，但本阶段只在任务模型中验证，没有改动真实 Task Scheduler。
4. 当前产物未做 Authenticode 代码签名，Windows SmartScreen 体验需在正式发布规划中评估。
5. ZIP 不是 bit-for-bit reproducible；内部文件 manifest 可重复，ZIP hash 每次构建重新生成且匹配。
6. `win-x64` 不覆盖 Windows on ARM 原生运行；本阶段未定义 arm64 资产。
7. 旧 `AutoLogin.ps1` 的内部日志版本仍为 1.2.5，这是保护登录核心不改动的结果，不影响 v1.3 产品安装版本，但 Phase 5/6 文案验收时需确认是否需要单独显示 Core Version。
