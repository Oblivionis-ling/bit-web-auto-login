# BIT-Web Auto Login v1.3 Phase 5.5 Report

## 1. 阶段结论

Phase 5.5 已完成。当前源码、构建脚本、Native Manager、Updater 与包验证器均能严格理解：

```text
1.3.0-rc.1 < 1.3.0-rc.2 < 1.3.0 < 1.3.1-rc.1 < 1.3.1
```

默认更新通道仍只调用官方仓库的 `releases/latest`，并同时拒绝 `draft=true`、`prerelease=true` 或 RC tag。隐藏 `--qa-release-tag` 只允许 RC Manager 查询同 base version 的指定 RC；它只改变 Release metadata endpoint，不改变下载与部署安全链。

本阶段没有 commit、push、tag、GitHub Release、真实安装、真实更新、计划任务修改、凭据读写或 Phase 6 快照。

## 2. 原始协议冲突

Phase 3～5 的更新协议只接受 `vMAJOR.MINOR.PATCH` 并用 `System.Version` 比较；Phase 6 则需要 `v1.3.0-rc.1 → v1.3.0-rc.2`。原实现还使用程序集数值版本与 PE `FileVersion` 做健康检查和包校验，两者都无法表达 RC ordinal。

本阶段将“产品发布版本”和“Windows 文件版本”明确拆开，避免把 `rc.1` 编码到不支持 prerelease 的 PE 数值字段中。

## 3. ReleaseVersion 模型

新增共享项目与受限模型：

```text
manager/BITWebVersioning/BITWebVersioning.csproj
manager/Shared/ReleaseVersion.cs
```

只接受：

```text
MAJOR.MINOR.PATCH
MAJOR.MINOR.PATCH-rc.N
```

其中数字不得有前导零，RC ordinal 必须从 1 开始。模型明确拒绝 `alpha`、`beta`、`preview`、`dev`、`nightly`、缺失 ordinal、`rc.0`、`rc.01`、两段版本以及其他任意 SemVer 扩展。

比较顺序先比较 Major / Minor / Patch；相同 base 下 RC 小于 Stable，两个 RC 按 ordinal 数值比较。代码不使用字符串比较，也没有引入第三方 SemVer 库。

## 4. ProductVersion 与 FileVersion

最终采用：

| 字段 | RC1 | Stable | 用途 |
| --- | --- | --- | --- |
| ReleaseVersion | `1.3.0-rc.1` | `1.3.0` | GitHub tag、更新比较、包、settings、manifest、Header、health check |
| ProductVersion | `1.3.0-rc.1` | `1.3.0` | 最终发布 EXE 的可读取 prerelease 身份 |
| InformationalVersion | `1.3.0-rc.1` | `1.3.0` | Manager 进程内产品版本来源 |
| AssemblyVersion | `1.3.0.0` | `1.3.0.0` | .NET 程序集兼容身份 |
| FileVersion | `1.3.0.0` | `1.3.0.0` | Windows PE 数值元数据，不参与 RC 顺序判断 |

`IncludeSourceRevisionInInformationalVersion=false` 确保最终 Informational/Product version 不被追加 commit suffix。Manager Header 与健康检查现在读取严格的 InformationalVersion；包验证器从真实 EXE 读取 ProductVersion，并额外确认 FileVersion 的 base version。

## 5. Stable 更新行为

普通“检查更新”继续使用固定 endpoint：

```text
GET https://api.github.com/repos/Oblivionis-ling/bit-web-auto-login/releases/latest
```

Stable 路径要求：

```text
draft=false
prerelease=false
tag=vMAJOR.MINOR.PATCH
```

Fake HTTP 测试证明：Stable metadata `1.2.5 → 1.3.0` 会发现更新；即使 stable endpoint 异常返回 `v1.3.0-rc.1` 且 `prerelease=true`，也会以 `UNSTABLE_RELEASE` 拒绝。普通通道没有枚举 prerelease、tag 查询或 channel 配置，因此不会发现 RC。

## 6. 隐藏 QA RC 行为

Phase 6 专用入口：

```text
BITWebManager.exe --qa-release-tag v1.3.0-rc.2
```

限制如下：

- 当前 Manager 必须自身为 `*-rc.N`；Stable Manager 直接以 `QA_MODE_REQUIRES_RC` 拒绝；
- 请求 tag 必须是受限 RC tag；
- 请求 RC 必须与当前 Manager base version 相同；
- 更低 RC 判为降级，不安装；相同 RC 判为当前版本；只有更高 RC 可更新；
- endpoint 固定为官方仓库 `/releases/tags/<严格 RC tag>`；不接受仓库、host 或 URL 输入；
- 响应必须满足 tag 完全相等、`draft=false`、`prerelease=true`。

QA 模式拿到 metadata 后，继续复用正式流程的 asset 精确命名、官方下载 URL、redirect allowlist、SHA-256、ZIP Slip、必要文件、credential 排除、settings/manifest/EXE 版本一致性、PowerShell Parser、Updater、backup、health check 和 rollback。没有 QA security bypass。

## 7. Build-Release

Stable canonical source 仍是 `manager/Directory.Build.props` 与源码 `settings.json` 中的 `1.3.0`。构建命令：

```powershell
# Stable
.\build\Build-Release.ps1

# RC1
.\build\Build-Release.ps1 -ReleaseVersion 1.3.0-rc.1

# RC2
.\build\Build-Release.ps1 -ReleaseVersion 1.3.0-rc.2
```

RC 参数必须显式指定；脚本不读取 tag、不自动递增。RC base 必须等于 canonical stable `1.3.0`。`rc.0`、`rc.01`、`beta.1` 与 `1.4.0-rc.1` 已实测在构建开始前拒绝。

构建通过 MSBuild properties 注入 Product/Informational version，保留数值 Assembly/File version；包内 `settings.json` 在 staging 中生成 RC Version，源码 `settings.json` 不变。包根目录、ZIP、SHA 与 manifest 使用同一个 ReleaseVersion。

## 10. Health check 与 Updater contract

真实运行最终发布 Manager：

```json
{"schemaVersion":1,"success":true,"version":"1.3.0","detail":null}
{"schemaVersion":1,"success":true,"version":"1.3.0-rc.1","detail":null}
{"schemaVersion":1,"success":true,"version":"1.3.0-rc.2","detail":null}
```

Updater 的 `--expected-version` 已改用 ReleaseVersion，并通过 `1.3.0-rc.2` 参数解析测试。部署后的 Manager 必须返回与 expected version 完全一致的产品版本；仅 base version 相同不再算健康。RC2 self-contained Updater 已独立启动并到达缺少 `--manager-pid` 的参数校验，退出码为 1，证明启动不依赖已安装的 .NET Runtime。

## 11. Validator

Stable、RC1、RC2 三份实际 ZIP 均通过同一个 `UpdatePackageValidator`：

- 固定单根目录；
- settings Version；
- release manifest Version/RID/入口；
- Manager/Updater ProductVersion 与数值 FileVersion；
- 必要文件与字体许可证；
- credential 禁入；
- ZIP Slip/symlink/展开大小限制；
- PowerShell Parser。

RC 没有单独、较弱的验证器。

RC1 Release ZIP 已通过完整隔离 Installer 测试：旧 `1.2.5` credential hash 保持、用户 settings 字段保留、Version 写为 `1.3.0-rc.1`、任务不重复、Shortcut 迁移、fresh install 与中途失败 rollback 均通过。测试目录位于系统临时目录，未操作真实安装。
