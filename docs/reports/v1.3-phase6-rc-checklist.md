# v1.3 Phase 6 RC 真机升级检查清单

本文件只准备 Phase 6 的真机演练材料；Phase 5.5 不执行升级、卸载、清除凭据、Git tag 或 GitHub Release。

## RC 源码与产物准备

Phase 6 只在人工确认 Phase 5.5 工作树后开始。RC 序号必须显式指定，禁止从 Git tag 猜测或自动递增：

```powershell
# RC1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build\Build-Release.ps1 `
  -ReleaseVersion 1.3.0-rc.1 `
  -OutputDirectory .\artifacts\phase6-rc1

# RC2
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build\Build-Release.ps1 `
  -ReleaseVersion 1.3.0-rc.2 `
  -OutputDirectory .\artifacts\phase6-rc2
```

发布前逐项确认：

- RC1/RC2 tag、ZIP 名、包根目录、`settings.json` 与 `release-manifest.json` 使用同一个 `1.3.0-rc.N`；
- Manager 与 Updater 的 `ProductVersion` 为 `1.3.0-rc.N`，`FileVersion` 均为 `1.3.0.0`；
- `BITWebManager.exe --health-check <path> --expected-version 1.3.0-rc.N` 返回同一个 RC 产品版本；
- ZIP SHA-256 与同名 `.sha256` 一致；
- Stable 默认构建仍为 `1.3.0`，默认 `/releases/latest` 路径拒绝 draft、prerelease 和 RC tag。

## 隐藏 RC QA 检查

RC1 安装完成后，只用 RC Manager 指定同基线、更高的 RC2：

```powershell
BITWebManager.exe --qa-release-tag v1.3.0-rc.2
```

该参数只改变 Release metadata 查询为官方固定 endpoint：

```text
GET /repos/Oblivionis-ling/bit-web-auto-login/releases/tags/v1.3.0-rc.2
```

必须确认返回 tag 完全一致、`draft=false`、`prerelease=true`。下载来源、redirect allowlist、SHA-256、ZIP Slip、必要文件、manifest、PowerShell 语法、Updater、健康检查和 rollback 均不得绕过。Stable Manager 必须拒绝此参数；RC2 指向 RC1 必须判为降级，指向 RC2 必须判为当前版本。

## 升级前快照

在确认本地输出位置后运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build\New-Phase6RcSnapshot.ps1 -AcknowledgeLocalMetadata
```

脚本只在 `artifacts/phase6-rc-snapshot/` 下写入快照，记录：

- `credential.xml` 是否存在及其 SHA-256；不复制凭据内容；
- `settings.json` 的本地备份；
- 计划任务 XML，以及 Action、WorkingDirectory、Arguments、Trigger、Principal 元数据；
- 开始菜单快捷方式目标、参数、工作目录和图标；
- 安装目录文件大小与 SHA-256 manifest。

快照包含本机用户名和路径等本地元数据，不应上传或加入 Git。

## Phase 6 演练顺序

1. 保存快照并确认 `credential.contentCaptured = false`。
2. 记录当前 Manager、产品版本和任务状态。
3. 创建经人工确认的 RC1 Source Commit、tag 和 GitHub Prerelease，并上传精确命名的 ZIP/SHA 资产。
4. 使用可回滚的 `v1.3.0-rc.1` Release 资产执行旧版到 RC1 的升级。
5. 创建 RC2 后，从 RC1 使用 `--qa-release-tag v1.3.0-rc.2` 完成真实 self-update。
6. 比较升级前后 credential SHA-256，必须完全一致。
7. 比较 settings 用户字段、任务数量与任务详细配置。
8. 验证 Native Manager、开始菜单图标、状态读取、Header RC 版本和健康检查。
9. 验证更新失败时的 backup / rollback。
10. 完成后删除只包含本地 QA 元数据的快照目录。

## 中止条件

- 凭据哈希变化；
- 出现重复计划任务；
- Shortcut 仍指向 legacy GUI；
- Manager 或 Updater 需要已安装的 .NET；
- 健康检查失败且未自动回滚；
- Stable Manager 接受 `--qa-release-tag`，或普通 `/releases/latest` 能发现 prerelease；
- RC metadata 与请求 tag、prerelease 标记或同基线约束不一致却仍继续；
- 安装器留下半更新状态。
