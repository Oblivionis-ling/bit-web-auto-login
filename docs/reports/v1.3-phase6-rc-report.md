# BIT-Web Auto Login v1.3 Phase 6 RC Report

## 1. 结论

Phase 6 在不可变 RC 纪律下完成，最终候选为 `v1.3.0-rc.5`。

本阶段真实完成了：

- 当前电脑旧版 `1.2` 到 GitHub RC1 的安装迁移；
- RC1 从真实 GitHub 查询、下载并验证后更新到修复候选 RC3；

## 6. RC1 → RC2 失败与 RC3 修复

RC2 metadata、ZIP、SHA 和 payload 均从真实 GitHub 下载并验证成功，但 Updater 在替换事务前退出：没有 `update-result.json`、没有 backup、正式目录保持 RC1。

根因是 RC1 Manager 启动 helper 后立即关闭，而 Updater 用 `GetProcessById` 验证来源；在 helper 获得进程对象前 PID 已消失，形成真实竞态。

RC3 修复保留来源安全校验：

- Updater 验证自身 Windows direct-parent PID 等于参数中的 Manager PID；
- Manager 尚存在时继续验证 EXE 路径并等待退出；
- Manager 已退出时使用 Windows 保存的 direct-parent identity 完成可信交接；
- 不放宽 target、prepared path、repo、URL、SHA、ZIP、manifest、PowerShell 或 health-check 校验。

RC1 → RC3 随后真实成功。成功结果：

```json
{"schemaVersion":1,"success":true,"version":"1.3.0-rc.3","detail":null}
```

真实下载工作区中的 RC3 ZIP SHA-256 与 GitHub `.sha256` 一致。

## 7. GitHub 网络现象

RC1 下载期间多次出现 Socket 10054/10060。分段诊断确认：

- GitHub metadata 可读取；
- 失败集中在 `github.com` / `release-assets.githubusercontent.com` 的 TLS 或传输阶段；
- 本机 Windows 系统代理为 Clash `127.0.0.1:7890`；
- HTTP proxy、SOCKS 和直连在当时节点均出现连接重置；
- 用户将 Clash proxies 切换为 Global 后，真实 RC1 → RC3 下载及更新成功。

每次网络失败均发生在 helper handoff 之前；正式目录、credential、Task 均未变化。此现象说明更新失败边界安全，但当前下载器没有断点续传，弱网络下仍可能需要切换网络后重试。

## 14. 已知风险与 Phase 7 建议

1. GitHub Release 大文件下载对本机 Clash 节点/路由敏感；失败安全，但没有断点续传。Phase 7 Release Notes 应建议遇到连接重置时切换网络或代理节点后重试。
2. Update workspace 在 helper handoff 后可能保留在 `%TEMP%`，不影响正确性，但后续 `1.3.x` 可增加安全的延迟清理。
3. 应用未做 Authenticode 签名，SmartScreen 风险仍需在 Release Notes 说明，不阻塞 `v1.3.0`。
4. Phase 7 应以 `ee46530c1e7ab6095e3943152f948a059de1fe0c` 为最终源码候选，重新 clean build Stable、复核 ZIP/SHA 后再决定 merge/tag/Release。
