## 四、第二阶段：公网已正常时单次运行

保持当前公网正常，执行：

```powershell

```

通过标准：

- 退出码为 `0`。
- 日志出现 `Internet connectivity is healthy.`。
- 本次日志不应出现新的 `submitting portal authentication`，因为公网原本正常。
- 网页访问、即时通信等现有连接没有被脚本打断。

查看当天日志：

```powershell
Get-Content ".\logs\$(Get-Date -Format yyyy-MM-dd).log" -Encoding UTF8 -Tail 50
```

## 五、第三阶段：校园网未认证时自动恢复

这是核心验收。优先在校园网登录页使用正常“注销/下线”功能，使网卡仍保持连接、但公网认证失效。若没有注销功能，可以等会话自然过期。不要通过禁用网卡制造此场景。

确认普通网页已经无法访问后，执行：

```powershell
$started = Get-Date
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\AutoLogin.ps1 -Live -Once
$elapsed = (Get-Date) - $started
"ExitCode=$LASTEXITCODE ElapsedSeconds=$([math]::Round($elapsed.TotalSeconds,1))"
```

通过标准：

- 退出码为 `0`。
- 通常在 60 秒内、最迟在 120 秒内恢复公网。脚本会先用两个独立探测地址确认，并要求连续两轮失败。
- 日志依次出现：
  - `All connectivity probes failed (1/2)`
  - `failed all connectivity probes 2 consecutive times; submitting portal authentication`
  - `Authentication request accepted: HTTP 200`
  - `Portal authentication succeeded; Internet access is restored`
- 日志中没有账号、密码、认证请求正文或完整响应正文。

如果失败：

- 退出码通常为 `3`。
- 保留当天日志，不要反复高频运行。
- 先恢复正常网页登录，再根据日志定位。

## 六、第四阶段：前台持续监控与断线恢复

启动持续监控：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\AutoLogin.ps1 -Live
```

保持该窗口运行，另开一个 PowerShell 查看日志：

```powershell
Get-Content ".\logs\$(Get-Date -Format yyyy-MM-dd).log" -Encoding UTF8 -Wait -Tail 30
```

依次测试：

### 4.1 正常联网静置 10 分钟

通过标准：

- 公网始终正常。
- 没有每 30 秒重复写日志。
- 没有重复提交认证。
- 允许偶尔出现一次 `All connectivity probes failed (1/2)`，但下一轮恢复后不得进入认证。
- 如果刚完成过认证，5 分钟冷却期内即使探测暂时失败，也只能记录 `authentication cooldown`，不得再次提交登录。

### 4.2 手动注销校园网认证

保持网卡连接，仅在登录页正常注销。

通过标准：

- 监控通常在 60 秒内、最迟在 120 秒内确认公网不可用并自动恢复。
- 只产生一轮成功认证记录，不持续重复登录。
- 登录后最多进行 4 次公网验证；验证暂时失败时进入 5 分钟冷却，不立即重新认证。

### 4.3 手动断开再恢复连接

根据实际使用方式选择：

- Wi-Fi：由你手动断开 `BIT-Web`，等待约 60 秒，再手动连接或等待 Windows 自动连接。
- 有线：由你手动拔掉网线，等待约 60 秒，再插回网线。

通过标准：

- 断开期间日志只表示没有符合条件的连接，不尝试修改网卡。
- 恢复连接后，如果公网仍有效则保持在线；如果认证已失效则自动登录。
- 不出现快速无限重试。

测试结束后，在运行监控的窗口按 `Ctrl+C`。

执行：

```powershell

$LASTEXITCODE
```

通过标准：

- 退出码为 `2`。
- 日志说明没有符合条件的校园网络。
- 日志中没有新增 `submitting portal authentication` 或 `Authentication request submitted`。
- 脚本没有切换回 `BIT-Web`，也没有改变热点或网卡配置。

测试后由你手动恢复校园网连接。

## 八、第六阶段：安装持续运行并测试睡眠、重启

只有前五阶段全部通过后再执行。

### 6.1 先预览

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -WhatIf
```

确认输出为预览，系统未修改。

### 6.2 安装并立即启动

```powershell

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Diagnostics.ps1 -IncludeInternetCheck
```

通过标准：

- `Scheduled task installed` 为 `True`。
- `Scheduled task state` 为 `Running`。
- 只检测到一个 `AutoLogin.ps1 -Live` 进程。
- `Internet check` 为 `True`。

### 6.3 睡眠唤醒

让电脑正常睡眠至少 2 分钟，再唤醒并等待 60 秒，然后运行诊断：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Test-Diagnostics.ps1 -IncludeInternetCheck
```

通过标准：

- 任务仍为 `Running`。
- 公网正常；若认证过期，日志显示自动恢复。
- 没有第二个重复监控进程。

### 6.4 重启验收

正常重启 Windows 并登录，等待 60 秒，然后运行同一诊断命令。

通过标准：

- 无需手动启动脚本，任务自动进入 `Running`。
- 只有一个监控进程。
- 校园网络符合条件时公网可用。
- 当天日志有本次启动记录，没有连续报错。

说明：DPAPI 凭据绑定当前 Windows 用户，因此任务设计为“用户登录后启动”，不是登录界面出现前启动。

保持任务持续运行至少 24 小时，正常经历锁屏、短时睡眠和校园网会话变化。期间不手动重复启动脚本。

通过标准：

- 任务仍为 `Running`。
- 只有一个监控进程。

- 日志没有持续重复的 `ERROR`。
- 认证只在公网失效时发生，没有固定每 30 秒重复认证。
- 发生认证请求错误时，重试间隔逐渐增大，最长不超过 30 分钟；达到上限后仍持续尝试。
- 日志没有账号、密码或请求正文。

## 十、最终通过标准

满足以下条件即可保持持续运行：

1. 七个必需阶段全部通过。
2. 核心恢复测试至少成功两次：一次单次运行、一次后台持续监控。
3. 睡眠唤醒和重启登录后都能自行恢复。
4. 非校园网络上退出码为 `2`，没有发送认证。
5. 24 小时内没有重复进程、持续错误或高频认证。

如果只使用有线或只使用 Wi-Fi，另一种连接方式可以标记为“不适用”；如果日常两种方式都会使用，则应分别完成第三、第四阶段。

## 十一、回退方法

若持续运行阶段出现异常：

```powershell
Stop-ScheduledTask -TaskName "BIT-Web AutoLogin" -ErrorAction SilentlyContinue
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Uninstall.ps1
```

这只停止并删除自动启动任务，不会删除脚本、日志或加密凭据，也不会修改网络配置。恢复正常网页登录后，把当天日志保留下来用于排查。
